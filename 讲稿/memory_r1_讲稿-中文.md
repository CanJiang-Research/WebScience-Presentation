### Slide 2：1 Research Background and Significance（约 2.0 分钟）

> **【提示】** 先指左侧的“Knowledge Engineering: BUILD → MAINTAIN → USE”流程，再顺着箭头过渡到中间的三大瓶颈，最后重点结合右侧 (a)(b)(c) 三个小图把“Andrew 收养两只狗”的例子讲透。

从 Web Science 的学科视角来看，大模型智能体的长期记忆管理，本质上对应着知识工程的三个经典环节：知识构建（Build）、知识维护（Maintain）和知识使用（Use）。映射到智能体记忆中，构建就是把新事实写入记忆库（ADD），维护就是对已有记忆进行更新或删除（UPDATE / DELETE），而使用就是在提问时检索相关记录（RETRIEVE）。

但在真实的跨会话交互中，知识并不是静态不变的。早先对话里出现的一个事实，可能会直接影响很久以后另一个问题的答案。这就引出了当前智能体记忆面临的三大核心瓶颈：

第一，**跨会话写入的歧义**。当一条新事实到来时，系统必须判断它究竟是推翻并替换了旧记忆，还是在旧记忆基础上的补充延伸。光靠文本相似度，往往分不清这两种关系。  
第二，**噪声环境下的读取困难**。检索阶段一次可能召回几十条候选记忆，里面鱼龙混杂，智能体必须从中筛选出真正支撑当前问题的证据。  
第三，**稀疏监督信号**。现实中我们很难为每一次记忆的增删改都标注“标准操作标签”，我们往往只能在很久之后的问答环节，通过最终答案对不对，反向判断早先的记忆操作是否合理。

为了让大家更直观地理解，请看页面右侧的这个例子，也是论文贯穿全文的经典案例：  
在图 (a) 中，Andrew 在第一次会话里提到自己收养了一只叫 Buddy 的救助犬；在之后的另一次会话里，他又说收养了“另一只狗”，叫 Scout。注意这里“another dog”这个表述很关键，它意味着 Buddy 的记录依然有效，总共是两次收养。当后续有人提问“Andrew 一共收养了几只狗”时，正确答案显然是两只。

但是看图 (b)，传统的提示词驱动（Prompted）记忆管理器在检索到 Buddy 这条旧记忆后，容易把新事实误判为冲突信息，直接执行 `DELETE + ADD`——把 Buddy 删掉、只留下 Scout。等到提问时，即便系统检索出多达 60 条候选记忆，里面也只剩 Scout，回答智能体自然就错答成“1 只狗”。

而图 (c) 展示的 Memory-R1 则不同：它通过强化学习，学会在面对这类补充事实时执行 `UPDATE`，把 Buddy 和 Scout 合并保留在同一条记录里；到了问答阶段，再精准挑出这条合并后的证据，从而答出“2 只狗”。

总结来说，这篇论文的研究意义集中在右侧底部的三点：一是同时让智能体学会“怎么写记忆”和“怎么读记忆”；二是仅用下游问答的正确率作为结果奖励，通过 PPO 或 GRPO，在 LoCoMo 数据集仅 152 对问答样本上就能训练出这两个策略；三是在保留测试集之外，进一步验证了模型向 MSC 和 LongMemEval 基准的泛化迁移能力。

### Slide 3：2 Related Work（约 1.5 分钟）

> **【提示】** 沿着页面布局，先讲左上“外部记忆系统”与右下“证据选择”两条线，再讲右上“Search-R1”的启发与差异，最后落脚左下角“Positioning”并自然交接给 Presenter 2。

接下来我们看相关工作，这页 PPT 从两条主线和一个关键启发来定位 Memory-R1。

左上角是**外部记忆系统**。比如 ReadAgent 存储摘要记忆供后续阅读，A-Mem 构造结构化的记忆链接，Mem0 通过提示词让模型编辑记录，MemoryOS 则负责跨会话组织记忆。这些工作都在如何设计存储结构上下了很大功夫，但共同局限在于：它们依赖人工编写的提示词来决定增删改，很容易误删仍然有效的旧事实；而且某一条记忆可能对问题 A 有用，对问题 B 却是干扰项。

右下角是**证据选择**方向，代表方法是 RAG 和重排（Reranking）。它们的两难困境非常典型：如果召回的候选记录太少，关键事实可能被漏掉；如果召回得太多，真正有用的证据又会被淹没在大量噪声里。

而右上角的 **Search-R1** 给了论文最直接的启发：Search-R1 证明了可以用最终答案的正确性作为奖励，通过强化学习来优化中间的检索决策。但搜索和记忆管理有一个本质区别——搜索动作只负责为“当前任务”抓取外部信息，而一次记忆编辑会永久改变记忆库的状态，从而影响“未来所有任务”所能看到的证据。

因此，左下角总结了 Memory-R1 的清晰定位：它不再只靠固定指令去操作记忆，而是用强化学习训练两个协同的策略——一个学习怎样的写入操作能带来未来的正确答案，另一个学习如何在召回结果中提炼证据并作答。

## 第二部分：方法论与强化学习设计（Presenter 2 · 约 8.0 分钟）

### Slide 4：3.1 The Memory-R1 Architecture（约 1.2 分钟）

> **【提示】** 接过话筒，指向左侧架构图中的闭环（Policy Inputs ↔ Memory-R1 ↔ Memory Bank M），再快速对应右侧 01–04 四个数学符号步骤。

谢谢第一位同学的介绍，下面由我来为大家讲解 Memory-R1 的核心方法。

首先看整体架构。Memory-R1 的核心思想非常清晰：它把长期记忆管理拆解为**两个独立参数的策略智能体**——负责写入的 **Memory Manager（$\pi_{\text{write}}$）**，以及负责读取和作答的 **Answer Agent（$\pi_{\text{answer}}$）**。两者并不直接端到端联合反向传播，而是通过中间的**外部记忆库 $M$** 共享信息、异步协同。

我们可以对照右侧的四个步骤来走一遍数据流：  
- **第一步（Manager Input）**：在写入阶段，新出现的对话事实 $x$ 本身会作为查询，去记忆库里检索出相关的已有记录 $M_{\text{old}}$，两者共同构成管理器的当前状态 $s = (x, M_{\text{old}})$。  
- **第二步（Write Policy）**：写策略根据状态 $s$，从四种操作 `{ADD, UPDATE, DELETE, NOOP}` 中选择一个，对记忆库执行编辑，得到更新后的记忆库 $M'$。  
- **第三步（Read Policy）**：到了回答问题的阶段，问题 $q$ 会从记忆库中检索出一组候选记忆 $M_{\text{ret}}$，读策略（即 Answer Agent）需要从中蒸馏出真正有用的证据，再生成最终回答 $y$。  
- **第四步（Reward）**：最后，系统将生成答案 $y$ 与标准答案 $y^*$ 做精确匹配（Exact Match），得到奖励信号 $r$。

这里需要特别强调页面底部的一句话：**两个智能体是分开训练的**——训练其中一个时，另一个的参数保持冻结，从而把复杂的读写耦合问题解耦成两个稳定可优化的强化学习过程。

### Slide 5：3.2 Memory Operations and Distillation（约 1.3 分钟）

> **【提示】** 视线带观众扫一遍表格中绿色四行（写路径）与米色两行（读路径）的区分，再落到右下角三步流程图“Policy Decision → Bank Update → Frozen Answerer”。

这一页把 Memory-R1 涉及的六步操作拆解得非常清楚。表格前四行是**写路径**，全部由 Memory Manager 决策并作用于外部记忆库：  
- **ADD**：面对全新事实时，在记忆库中追加一条持久化记录；  
- **UPDATE**：将新事实与已有记录进行修正或合并，比如左下角例子里，把目标条目更新为“Andrew adopted Buddy and Scout”，既保留了旧信息又纳入了新信息；  
- **DELETE**：当旧记录已经过时或失效时，将其从记忆库中移除；  
- **NOOP**：这是一个非常关键的显式选项——如果已有记忆已经完整包含当前信息，就保持记忆库原封不动，避免不必要的改写引入错误。

表格后两行则是**读路径**的两个阶段：  
- **RETRIEVE**：根据用户问题，通过相似度检索从记忆库中召回最多 60 条候选记录；  
- **DISTILL（蒸馏）**：这是 Answer Agent 非常核心的一步。它不是把这 60 条候选直接一股脑塞进生成过程，而是先从中主动筛选出与问题直接相关的证据子集，再基于这个精炼后的子集生成回答。

请看右下角的流程图：在训练写策略时，管理器做出决策、更新记忆库，随后由一个**冻结的回答器**去作答并打分。这就把“记忆编辑的质量”直接转化成了“下游问答的得分”。

### Slide 6：Appendix A: Memory Across Dialogue Turns（约 1.2 分钟）

> **【提示】** 从左到右依次点过四个时间节点（First Adoption → Second Adoption → Question Time → Answer Time），再对比底部虚线框中 Baseline 与 Memory-R1 的行为差异。

为了把刚才的六步操作串联起来，我们用论文附录里细化的双收养场景走查一遍完整的跨轮对话轨迹。需要说明的是，这幅图是对真实对话轨迹的简化展示，用来说明行为机制，而不是代表整体准确率统计。

- 在**第一次收养**轮次，Andrew 提到收养了 Buddy，系统执行 `ADD`，记录下第一条收养信息。  
- 到了**第二次收养**轮次，Andrew 提到收养了“另一只狗”Scout。系统先检索相关记忆找到 Buddy，关键就在于能不能理解“another”代表累加而非矛盾。强化学习训练后的 Memory-R1 会执行 `UPDATE`，把 Buddy 和 Scout 合并在同一条记录中；而底部的提示词基线则把它误当成矛盾事实，删掉了 Buddy、只新增了 Scout。  
- 到了**提问阶段**，系统问“跨会话下来 Andrew 一共收养了几只狗？”，`RETRIEVE` 步骤返回最多 60 条候选记忆。  
- 最后在**作答阶段**，Memory-R1 的 `DISTILL` 步骤从 60 条候选里精准选中同时包含 Buddy 和 Scout 的那条合并记录，轻松答出“2 只狗”；反观基线系统，因为记忆库早已被破坏，无论怎么检索也只能答出“1 只狗”。

这个案例很直观地说明：长期记忆之所以难，是因为写阶段的一次误操作，会在很久之后的读阶段造成无法挽回的信息丢失。

### Slide 7：3.3 Constructing Training Examples（约 1.4 分钟）

> **【提示】** 重点讲清楚“为什么必须先重建并保存记忆快照（Snapshot）”，以及 Manager 和 Answerer 两条独立的数据构建路径。

既然下游答案的反馈存在明显的延迟，那么论文具体是怎么构建训练样本的呢？这页展示了完整的三步流程，注意其中第二步和第三步对应的是**两条独立的数据构建路径**。

- **第一步：重建历史记忆快照（Rebuild the memory bank）**。对于每一条与标准问答对关联的目标对话轮次，作者按时间顺序处理此前的所有历史会话，利用 GPT-4o-mini 提取、合并并保存该轮次**之前**的记忆库状态，也就是一个“快照”。为什么要费工夫存快照？原因很实际：只有固定住同一个初始记忆库和同一个测试问题，我们才能在后续强化学习采样多个候选编辑时，让冻结的回答器在完全公平的基准上给不同编辑打分。  
- **第二步：训练写策略（Train the write policy）**。从快照出发，把新事实和相关旧记忆喂给 Memory Manager，让它采样编辑操作；把编辑应用到快照上，再用冻结的回答器检索并作答、计算得分。  
- **第三步：训练证据选择策略（Train the evidence-selection policy）**。这里输入的是问题和检索出的候选记忆——具体来说，是针对对话双方每位说话人各检索最多 30 条，合起来最多 60 条候选。Answer Agent 对这些候选做蒸馏筛选并生成答案，直接用标准答案提供监督。

补充一点数据规模：整套训练只用了 LoCoMo 中 **152 对问答样本**，配合它们对应的对话历史和重建出的记忆快照。页面底部再次点出了这一设计的核心理念——通过下游问答把“延迟效应”反向传导给早先的记忆编辑。

### Slide 8：3.4 PPO and GRPO for Memory Policies（约 1.8 分钟）

> **【提示】** 这一页公式和数字较多，是方法部分的重头戏。语速稍微放慢，先明确“顶部三样本是我们为了演示公式构造的数值算例，不是论文报告的一次实际运行”，再一步步把 GRPO 的组内归一化优势讲透，最后对比 PPO 与 GRPO 的更新机制。

有了训练样本，接下来看如何用 PPO 和 GRPO 来优化策略。为了让大家对 GRPO 的优势估计有一个直观手感，页面上半部分我们结合前面的收养案例，构造了一个组大小 $G=3$ 的数值演示算例（注意这是一个教学算例，并非论文某次实际训练日志）：

看左上角 **01 Sample and Score**：在同一个状态 $s$ 下，写策略采样了三个候选编辑。样本 1 执行了正确合并两只狗的 `UPDATE`，冻结回答器答出“2 只狗”，精确匹配奖励 $r_1 = 1$；样本 2 虽然也选了 `UPDATE`，但把 Buddy 覆盖掉了，只答出“1 只狗”，$r_2 = 0$；样本 3 选择了 `NOOP` 什么也不改，同样只答出“1 只狗”，$r_3 = 0$。

看中间 **02 Compare Within a Group**：GRPO 不需要额外训练一个价值网络（Critic），而是直接在这一组样本内部做标准化。三个奖励 $(1, 0, 0)$ 的均值 $\mu = 1/3$，总体标准差 $\sigma = \sqrt{2}/3 \approx 0.471$。用公式 $A_i = (r_i - \mu)/\sigma$ 算出每个样本的优势值：正确合并的样本 1 获得 $+1.41$ 的正优势，而覆盖旧记忆或无作为的样本 2、样本 3 各自得到 $-0.71$ 的负优势，且组内优势之和恰好为 0。

看右上角 **03 Interpret the Advantage**：这就非常清晰地告诉策略网络——在同一个输入状态下，哪些编辑优于同组平均水平，应当提高概率；哪些低于平均水平，应当受到抑制。

再看下半部分 **04 Update One Policy at a Time**：  
GRPO 的目标函数由两项组成：第一项用重要性采样比率 $\rho_i = \pi_\theta(a_i|s)/\pi_{\text{old}}(a_i|s)$ 乘以组内优势 $A_i$，引导高优势动作提升生成概率；第二项是 $-\beta D_{\text{KL}}(\pi_\theta \parallel \pi_{\text{ref}})$，通过相对参考策略的 KL 散度惩罚来防止模型在优化过程中偏离过远、保持策略稳定。  
作为对比，**PPO** 则是靠一个可学习的 Critic 网络来估计优势函数，并通过裁剪比率 $\text{clip}(\rho) \in [1-\varepsilon, 1+\varepsilon]$ 来限制单步更新幅度。

右下方总结了整个训练循环与信用分配：每次冻结搭档、只更新活跃策略。对于管理器，由冻结回答器的输出决定奖励；对于回答器，则直接由自身输出的精确匹配得分决定奖励。

### Slide 9：3.5 Outcome-Based Reward Design（约 1.1 分钟）

> **【提示】** 明确点出三行是三个独立的例子、分数不相加，并强调“只看最终结果、不给中间操作贴标签”的极简奖励设计，然后自然交接给 Presenter 3。

方法部分的最后一页，我们专门来看一下奖励函数的设计。Memory-R1 采用的是非常纯粹的**基于结果的二值精确匹配奖励（Binary EM）**：只要最终生成的答案 $\hat{y}$ 与标准答案 $y^*$ 精确一致，奖励就是 1；不一致就是 0。

页面上的三行是三个彼此独立的示例，它们的分数并不相加：  
- 前两行展示的是训练 Memory Manager 时的反馈：当管理器通过 `UPDATE` 保留了两只狗的名字，冻结回答器答出“2 dogs”，管理器获得奖励 1；如果它把 Buddy 覆盖掉只留 Scout，冻结回答器答出“1 dog”，奖励就是 0。  
- 第三行展示的是训练 Answer Agent 时的反馈：此时管理器固定不动，检索出最多 60 条候选记忆，只要回答器通过 `DISTILL` 选对证据并答出“2 dogs”，它自己就获得奖励 1。

值得思考的是，这种奖励机制没有任何针对“选了哪条证据”或“选了哪个操作”的过程监督标签，完全由最终结果驱动。那么，如此简洁的奖励在真实长对话基准上究竟表现如何？又会在哪些场景暴露出局限？下面有请第三位同学为大家带来实验结果与深入讨论。

第二，对比强基线 Memory-SFT，GRPO 在 LLaMA 上将 Judge 分数提升了 **+3.98 分**，在 Qwen 上提升了 **+0.38 分**。  
第三，有意思的是，**PPO 在两个模型上的总体 Judge 分数反而不如 SFT**（LLaMA 57.54 vs. 58.76；Qwen 59.53 vs. 61.13），这已经初步反映出不同强化学习算法在稀疏结果奖励下的稳定性差异。

### Slide 11：4.2 Main Results（约 1.5 分钟）

> **【提示】** 按左、中、右三栏推进：先看左图 Judge 均值跃升，再看中图词面重合度双升，最后重点停留在右表和底部灰条——讲出“整体涨分掩盖题型分化”的批判性洞察。

这一页我们把主实验结果拆得更细，从三个维度观察。

左侧两张图对比了各方法的总体 Judge 分数：虚线标出了 A-Mem、Mem0、MemoryOS 和 Memory-SFT 四个基线的均值（LLaMA 为 49.35，Qwen 为 51.62），可以看到 Memory-R1-GRPO 稳居最高点，优势在 LLaMA-3.1-8B 上尤为明显。

中间的柱状图对比了词面重合度（Answer Overlap）。相比于 Memory-SFT，GRPO 在两个基座模型上都实现了 F1 和 BLEU-1 的同步增长：在 LLaMA 上，F1 从 42.81 提到 45.02（+2.21），BLEU-1 从 32.98 提到 37.51（+4.53）；在 Qwen 上，F1 从 39.51 提到 43.14（+3.63），BLEU-1 更是提升了 +5.60。这说明在精确匹配奖励的约束下，模型输出不仅语义更准，而且表达更凝练、更贴合标准答案。

不过，真正值得我们细看的是**右侧按问题类型拆解的表格**，这里揭示了一个非常关键的现象：  
- 在 **LLaMA-3.1-8B** 上，GRPO 最大的增益来自**时间推理题（Temporal）**，Judge 分数从 SFT 的 37.35 暴涨到 53.01，整整高了 **+15.66 分**；多跳题和开放域题也有稳定提升。但在最简单的**单跳题（Single-hop）**上，GRPO 反而比 SFT 下降了 3.10 分（54.65 → 51.55）。  
- 而在 **Qwen-2.5-7B** 上，情况又变了：GRPO 在多跳题上提升显著（57.74 → 62.34），但在时间推理题上却跌到了 40.96，反而是 PPO 在 Qwen 的时间推理题上拿到了 53.01 的高分。

正如页面底部总结的：**不同题型之间存在权衡，整体平均分的提升，完全可能与单跳题或时间题的局部下滑并存**。因此，只看一个总平均分，很容易忽略模型能力和题型特征带来的细粒度差异。

先看下半部分的 **GRPO 消融**：

综合全文，我们在页面下方梳理了论文的三大局限，并将它们与 Web Science 的核心研究命题对应起来：  
- **L1：答案级单点监督的盲区（对应知识维护 Knowledge Maintenance）**。目前每次记忆编辑只通过“一个”下游问答探针来打分，这只能暴露编辑影响的一小部分。作为我们小组的延伸思考，未来可以通过**多探针评测**，同时检验被修改的事实以及理应保留的旧事实，防止模型“顾此失彼”。  
- **L2：以纯文本对话为中心的评测局限（对应知识表示 Knowledge Representation）**。当前实验局限于多轮文本聊天，未来需要拓展到多模态信息与更复杂的真实世界 Web 记录。  
- **L3：双智能体分离训练的局限（对应知识集成 Knowledge Integration）**。目前训练时必须冻结一方、更新另一方，未来值得探索读写联合训练机制，检验同步更新能否进一步提升记忆的召回与利用效率。

## 附：排练节奏与高频 Q&A 参考

1. **为什么不用端到端联合训练，而要冻结一方、分开训练？**  
   两个策略之间隔着离散的外部记忆库编辑操作与检索过程，如果同时更新，记忆库分布和读取策略都在剧烈变化，会导致信用分配极不稳定；冻结搭档可以把问题解耦为两个平稳的策略优化任务（同时也正如 Slide 14 的 L3 所指出的，如何稳定地实现联合训练是值得探索的未来方向）。
2. **训练只用了 152 对 QA，为什么不会严重过拟合，还能迁移到 LongMemEval？**  
   152 指的是 QA 对的数量，但每条样本背后都伴随完整的多轮对话历史和重建出的记忆快照；同时强化学习通过组内多样本采样探索不同编辑决策，加上 GRPO 中的 KL 散度正则化约束了模型不偏离参考策略，从而学会的是通用的“何时合并/何时保留/如何筛选证据”的元策略，而非死记具体对话内容。
3. **为什么在 LLaMA 和 Qwen 上，GRPO 相比 SFT 的提升幅度差那么多（+3.98 vs. +0.38）？**  
   一方面，Qwen-2.5-7B 本身在 Memory-SFT 上起点已经较高（61.13 vs. LLaMA 的 58.76）；另一方面，从 Slide 11 的题型拆解可以看出，Qwen-GRPO 在多跳题上提升明显，但在时间推理题（Temporal）上有所下滑（46.99 → 40.96），拉低了整体 Judge 增幅，不过在 F1（+3.63）和 BLEU-1（+5.60）上 Qwen-GRPO 的提升依然很显著。
4. **既然 Exact Match 这么严格，会不会误杀语义正确但表述不同的答案？**  
   确实存在这种风险，但 Slide 13 的 Table 2 实验展示了另一面的权衡：换成更宽松的 LLM Judge 奖励后，Judge 分数虽然从 57.54 涨到 63.58，但模型倾向于输出更长、更冗余的答案，导致 F1（41.05 → 33.69）和 BLEU-1（32.91 → 23.36）大幅下滑。因此论文在精确性与简洁性之间选择了更严格的二值 EM 作为主奖励。
